# 产品查找与维护

本轮完成本地目录改造，尚未部署。保留产品网址、型号表、参数和图片。

## 客户入口

- 英阿产品总览直接展示49 个产品系列展开后的 73 个产品／款式入口，按 9 个分类分组；点击图片或名称即可打开详情。
- 总览可按分类筛选，或按英文、阿语产品名称搜索。支持组合筛选、清除筛选和无结果提示。
- 搜索当前覆盖产品／款式名称与分类词，不宣称覆盖全部工厂型号或规格。
- 搜索词与分类保存到 URL，并用会话存储兼容本地文件访问；浏览器返回、刷新、再次从详情进入总览均可恢复。清除筛选同时更新保存状态。
- 直通／斜角消防栓系列在总览和分类卡片增加直通、斜角螺纹、斜角法兰三个入口，链接到详情页对应图片及选型参数。款式入口由该产品 gallery、copy 和 configurationCards 数据生成，保留原系列网址。
- 电脑产品菜单按分类展示直达链接；手机先显示分类，展开后选择产品。
- 首页产品区新增查看全部产品按钮；所有分类卡片也直接打开总览并自动筛选，不再进入中间目录页。
- 总览的产品内容由服务端生成；关闭 JavaScript 时仍能查看和打开所有产品，交互筛选控件保持隐藏。

## 后续新增产品

继续维护 `site-src/_data/productDirectory.js` 这一份目录清单。菜单、总览、搜索数据和分类页均从清单生成，不再分别手改这些入口。

新增一个产品系列时：

1. 按既有数据模板准备产品资料、英阿文案、已确认参数与获准图片。
2. 在 `site-src/_data/siteRoutes.js` 登记稳定网址，使用对应产品模板生成页面。
3. 在统一目录清单的所属分类登记产品路由、英阿名称和主图。构建后上述查找入口自动同步。
4. 运行 `npm run build` 和相应浏览器验证，再按发布流程处理。

同系列新增尺寸或温度优先更新产品型号表，不增加目录层级。产品资料与目录摘要目前仍是不同的数据职责：更改名称或主图时应同步清单，现有文档产品校验会检查两者一致性。可视化后台、任意型号搜索和完整草稿工作流未在本轮建设；既有图片许可和发布状态继续保留。

## 验证

- 构建包含 127 个页面的路由、SEO、导航与产品内容校验。
- `tools/validate-listings.mjs` 验证总览中的每个产品都有直接入口，数量与目录清单一致。
- `tools/validate-product-discovery-browser.mjs` 检查 7 个代表页面的 1440、768、390、320 像素布局，以及搜索、组合筛选、重置、菜单关闭和手机分类展开。
- 截图与结果在 `docs/evidence/product-discovery/`。

先前 `outputs/eight-products-release-candidate/` 是仅上架 8 款新品的旧站适配包，不包含本轮整站导航改造。正式发布本轮改动时需重新准备相应范围的发布版本。

## 全站两级规则

第一级是总览及分类筛选，第二级是产品详情或同一详情中的明确款式。总览不再链接到中间分类目录。现有分类网址保留兼容旧链接，内容同样直接展示产品。

productViews.js 明确列出具有独立图片的款式，复用原始名称、图片和技术资料。包装、近景、不同拍摄角度和尺寸／温度选项不另建目录。款式卡片通过 view 参数打开对应图库图片，已逐项验证英阿页面。旧产品网址保留，不把用户可见的两级导航误改成磁盘目录迁移。

## 目录图片性能

目录及分类卡片使用 480 像素 WebP 缩略图，详情页继续使用原图。构建前自动运行 `npm run thumbnails`，需要 Python 与 Pillow；按原图内容哈希缓存，图片更换后会生成新文件。消防器材箱加入后，全站目录共 73 个直接产品入口；缩略图数量和体积以当前构建结果为准。

总览先恢复筛选，再用 IntersectionObserver 加载可视区域及前后 900 像素的图片；未选分类不触发加载。关闭脚本时使用 noscript 图片兜底。尺寸占位与异步解码减少布局移动和主线程等待。

`tools/validate-catalog-performance.mjs` 验证英阿页面、1440/390 宽度、file/HTTP 模式，共 8 组通过。测试首屏桌面加载 4–8 张、手机 1 张，水泵接合器筛选未加载其他分类图片，滚动及切换分类加载通过。该数据为本地测试，不等同于线上网络耗时承诺。记录见 `docs/evidence/catalog-performance/browser-validation.json`。

针对 products.html?q=&category= 的图片等待问题，改为筛选恢复后立即请求首屏和下方 900 像素范围内的缩略图，首屏请求标记高优先级。更远图片继续通过观察器加载。此轮独立浏览器测试首批桌面图约 565ms 加载完成；这不是用户当前浏览器的复现数据，实际仍受浏览器环境影响。证据：docs/evidence/catalog-performance/exact-page-after.json。

## 全部产品分页

当前 73 个直接产品入口按每页 12 款展示，共 7 页。脚本缓存全部目录数据，但只将当前页卡片保留在页面 DOM 中；搜索和分类先匹配全目录，再分页。修改筛选回到第一页，页码与搜索／分类一起保存在 URL 和会话状态中。上下翻页按钮在边界禁用，结果不超过 12 款时隐藏分页。无脚本环境继续提供完整静态目录。

分页回归由 `tools/validate-catalog-pagination.mjs` 执行，覆盖英阿、桌面／手机、file／HTTP 共 8 组，并从目录数据动态计算总入口数、总页数和末页数量，同时验证全目录搜索、无结果、返回和刷新恢复页码。此前以一次展示全部卡片为前提的性能测试不再作为分页验收，应使用该测试。

## 分页图片即时加载修复

复现：390px 本地预览从第一页底部点击下一页，旧逻辑有 11/12 张图片仍未请求，因为先按旧滚动位置判断再滚回顶部。分页后不再使用 IntersectionObserver 或距离阈值：每次更新立即请求当前页全部缩略图（最多 12 张），前 4 张提高优先级，非当前页仍不挂载。这取代前述全量目录时期的按视口预加载策略。

分页测试交替从顶部／底部点击下一页，同步检查没有 data-src 待请求图片，并等待所有当前页缩略图解码成功；覆盖 file/HTTP、英阿和桌面／手机。
